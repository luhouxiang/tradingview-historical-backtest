# 缠论算法详细说明文档

本文档按当前程序实现说明缠论算法，而不是按理论教科书重新定义。当前权威实现位于 `python/src/tvbt/chan/`，核心入口为 `algorithm.py`，核心引擎为 `engine.py`，参考结构扫描为 `reference.py`，背驰与买卖点为 `signals.py`。

当前算法定义：

- `algorithm_id`: `chan_engineering`
- `algorithm_version`: `5.0.0`
- `calculation_mode`: `causal_events`
- 唯一可配置参数：`checkpoint_interval`
- 输入：标准化 K 线 Parquet 中的 `bar_index`、`timestamp_utc`、`high_i64`、`low_i64`、`close_i64`
- 输出：分型、笔、笔中枢、段、段中枢、走势状态、Z/Zn 监视、背驰、买卖点和因果事件流

## 1. 总体因果模型

缠论引擎逐根接收原始 K 线。每根 K 线必须满足：

- `bar_index` 连续递增。
- `timestamp_utc` 严格递增。
- `low_i64 <= high_i64`。

所有语义对象都通过 `EventEmitter` 生成 `upsert` 或 `delete` 事件。事件包含：

- `event_seq`：确定性递增序号。
- `known_at_bar_index`：对象在因果上可被知道的 K 线位置。
- `object_type`：对象类型。
- `object_id`：稳定 ID。
- `object_revision`：对象语义变化版本。
- `payload_json`：对象当前语义。

对象可以在后续 K 线中被修订或删除。回放和前端只能在 `known_at_bar_index` 到达后应用对应事件，不能提前使用完整历史终态。

## 2. 包含关系与独立 K 线

分型之前先把原始 K 线转换为独立 K 线。每根新原始 K 线先构造一个候选独立 K 线，默认方向为 `down`，然后与最后一根独立 K 线比较。

### 2.1 直接新增独立 K 线

满足以下任一条件时，新 K 线直接成为新的独立 K 线：

- 当前 `high_i64 > 前一独立K线.high_i64` 且 `low_i64 > 前一独立K线.low_i64`，方向记为 `up`。
- 当前 `high_i64 < 前一独立K线.high_i64` 且 `low_i64 < 前一独立K线.low_i64`，方向记为 `down`。

### 2.2 包含关系合并

不满足直接新增条件时，当前 K 线与前一独立 K 线存在包含或重叠，程序会替换最后一根独立 K 线。

已有方向为 `up` 时：

- 合并后高点取两者高点最大值。
- 合并后低点取两者低点最大值。
- 高点或低点若来自当前 K 线，同时更新对应时间和原始 K 线索引。

已有方向为 `down` 时：

- 合并后高点取两者高点最小值。
- 合并后低点取两者低点最小值。
- 高点或低点若来自当前 K 线，同时更新对应时间和原始 K 线索引。

首个二元关系有一段特殊处理：当独立 K 线列表只有一根且该独立 K 线还只覆盖一根原始 K 线时，程序用当前 K 线是否向右扩张来决定高低点来源。这是为贴合参考实现的起始包含语义。

每根独立 K 线保留：

- 覆盖的原始 K 线起止索引。
- 高点、低点及其对应时间和原始索引。
- 最近一次确认时间。
- 来源原始 K 线索引列表。

## 3. 分型

分型只在新独立 K 线被追加时尝试生成。包含合并不会立即封存新的分型。

当新独立 K 线追加后，程序检查倒数第二根独立 K 线，也就是三根窗口中的中间 K 线：

```text
left, center, right
```

### 3.1 顶分型

顶分型条件为：

- `center.high_i64 > left.high_i64`
- `center.high_i64 > right.high_i64`
- `center.low_i64 > left.low_i64`
- `center.low_i64 > right.low_i64`

也就是说，当前实现要求中间独立 K 线的高点和低点都严格高于左右两侧。

### 3.2 底分型

底分型条件为：

- `center.high_i64 < left.high_i64`
- `center.high_i64 < right.high_i64`
- `center.low_i64 < left.low_i64`
- `center.low_i64 < right.low_i64`

也就是说，当前实现要求中间独立 K 线的高点和低点都严格低于左右两侧。

### 3.3 分型锚点与确认时间

顶分型：

- 锚点使用中间独立 K 线的高点。
- `bar_index` 使用高点来源原始 K 线索引。
- `time` 使用高点来源时间。
- `price_i64` 使用高点价格。

底分型：

- 锚点使用中间独立 K 线的低点。
- `bar_index` 使用低点来源原始 K 线索引。
- `time` 使用低点来源时间。
- `price_i64` 使用低点价格。

分型由右侧独立 K 线封存：

- `confirmed_at_bar_index = right.end_raw_index`
- `known_at_bar_index = confirmed_at_bar_index`

分型 ID 由分型类型、锚点时间、确认位置和价格生成稳定哈希。

## 4. 笔

笔由分型队列生成。当前实现参考 `kline-chart/algo-ui` 的 `c_bi.get_node/satisfy_the_number` 选择规则。

### 4.1 待处理分型队列

每个已确认分型进入 `_pending_fractals`。队列第一个分型作为当前候选笔起点。生成一笔后，被选中的终点分型会保留为下一笔的起点，因此相邻笔首尾直接相接。

### 4.2 最少独立 K 线数量

常量 `REFERENCE_MIN_INDEPENDENT_BARS = 5`。候选终点与起点之间的独立 K 线跨度必须满足：

```text
endpoint.normalized_index - base.normalized_index + 1 >= 5
```

不足 5 根时，程序继续寻找后续相反类型分型。

### 4.3 终点选择与同类极值替换

程序先找到起点之后第一个相反类型分型作为候选终点。然后向后扫描：

- 如果后续分型与候选终点同类，且更极端，则替换候选终点。
- 起点为顶分型时，候选终点是底分型，后续更低的底分型会替换终点。
- 起点为底分型时，候选终点是顶分型，后续更高的顶分型会替换终点。

替换后，新的候选终点同时成为后续确认间隔的基准。

### 4.4 后续分型区间确认

候选终点不是一出现就确认。程序继续寻找与起点同类的后续分型，并要求该分型与候选终点之间再次满足最少 5 根独立 K 线跨度。

随后检查价格分离：

- 起点为顶分型时，后续同类顶分型所在独立 K 线的 `low_i64` 必须大于候选底分型所在独立 K 线的 `high_i64`。
- 起点为底分型时，后续同类底分型所在独立 K 线的 `high_i64` 必须小于候选顶分型所在独立 K 线的 `low_i64`。

满足价格分离后，候选终点确认成笔，确认时间使用这个后续分型的 `known_at_bar_index`。

### 4.5 笔方向与事件时间

笔方向由起点分型决定：

- 起点为底分型，终点为顶分型，方向为 `up`。
- 起点为顶分型，终点为底分型，方向为 `down`。

笔的 `known_at_bar_index` 取以下最大值：

- 参考选择返回的确认位置。
- 释放本批笔的当前分型 `known_at_bar_index`。
- 前一笔的 `known_at_bar_index`。

这样可以保证一次分型释放多笔时，事件时间不倒退。

### 4.6 临时笔

如果候选终点满足跨度和极值替换规则，但还没有后续分型完成价格分离确认，程序会输出一条 `confirmed=false` 的临时笔：

- 对象类型仍为 `bi`。
- ID 形如 `bi-provisional-*`。
- 后续确认正式笔时会删除临时笔。
- 临时笔不进入 `self.bi`，因此不会参与笔中枢、段和信号计算。

## 5. 笔中枢

笔中枢由 `reference_centers(self.bi)` 计算，只使用已确认笔。当前实现是对参考算法 `compute_bi_pivots/process_down_up` 的移植。

### 5.1 扫描起点

笔数量少于 5 时不生成笔中枢。扫描从 `base = 1` 开始，而不是从第 0 笔开始。

每轮使用：

```text
base
seed_end = base + 2
```

这两个同奇偶位置的笔构成候选中枢核心。

### 5.2 核心重叠区间

对一笔：

- `low = min(start.price_i64, end.price_i64)`
- `high = max(start.price_i64, end.price_i64)`

候选核心：

```text
ZD = max(low(base), low(seed_end))
ZG = min(high(base), high(seed_end))
```

如果 `ZD > ZG`，没有重叠，不生成中枢。注意笔中枢允许 `ZD == ZG` 的点接触兼容情况。

如果有重叠，则生成中枢核心。核心区间在后续延长过程中保持冻结，不随延长笔重新收窄或放宽。

### 5.3 延长与离开

从 `cursor = base + 4` 开始，每隔两笔检查一次。只要该笔与冻结核心仍有重叠，就延长中枢：

```text
max(ZD, low(cursor)) <= min(ZG, high(cursor))
```

如果后续同奇偶笔不再与核心重叠：

- 中枢状态为 `left`。
- `exit_index = cursor`。
- 若 `low(cursor) > ZG`，`leave_direction = up`。
- 否则 `leave_direction = down`。

如果没有离开：

- 只有三笔构件时状态为 `confirmed`。
- 超过三笔构件时状态为 `extended`。

### 5.4 输出字段

笔中枢输出为 `zhongshu`：

- `analysis_level = stroke`
- `component_kind = bi`
- `component_count` 使用从 `base` 到 `end_index` 的完整笔切片数量。
- `zd_i64` / `zg_i64` 是冻结核心。
- `dd_i64` / `gg_i64` 是参与切片所有笔的完整外包络。
- `z_i64 = (ZD + ZG) // 2`
- `confirmed = true`
- `confirmed_at_bar_index = reference_center.known_at_bar_index`
- `known_at_bar_index` 在事件发出时不早于当前触发结构更新的笔。

对象 ID 由核心起始笔和种子结束笔生成。

## 6. 段

段由 `reference_segments(self.bi, self.raw_bars)` 计算，只使用已确认笔和原始 K 线。当前实现是对参考 `_NCHDUAN` 的移植。

### 6.1 输入视角

段扫描中，程序把笔方向翻转为参考实现的 `side` 视角：

```text
_flipped_side_up(line) = line.direction == "down"
```

段扫描判断高低点时，使用的是每笔起点对应的原始 K 线：

```text
bars[line.start.bar_index]
```

这是当前实现为贴合参考算法保留的行为。

### 6.2 首段发现

笔数量少于 4 时不生成段。扫描从第 3 笔开始。

首段发现先要求当前笔与三笔前存在参考重叠：

- 翻转后为上时：`current_bar.high_i64 >= previous_bar.low_i64`
- 翻转后为下时：`current_bar.low_i64 <= previous_bar.high_i64`

没有重叠时，最小/最大候选重置。

有重叠后，在 `current-3` 到 `current-1` 中维护局部高点和低点候选。随后按参考规则判断首个向上段或向下段：

向上段：

- 当前翻转方向为上。
- 当前高点更新局部高点。
- `current - minimum >= 3`。
- 当前高点突破 `current-2` 起点 K 线高点。
- `current-1` 起点 K 线高点突破 `current-3` 起点 K 线高点。
- 段起点为局部低点笔，终点为当前笔。

向下段：

- 当前翻转方向为下。
- 当前低点更新局部低点。
- `current - maximum >= 3`。
- 当前低点跌破 `current-2` 起点 K 线低点。
- `current-1` 起点 K 线高点低于 `current-3` 起点 K 线高点。
- 段起点为局部高点笔，终点为当前笔。

向下段最后一步使用高点对高点比较，这是程序中明确保留的参考实现行为。

### 6.3 段确认与临时段

首段发现后，程序维护两个对象：

- `segment`：当前主段。
- `temporary`：可能形成的反向临时段。

后续每笔调用 `_confirm_up_segment` 或 `_confirm_low_segment`。返回值语义：

- `-1`：尚不能确认。
- `0`：当前主段确认，随后开始反向主段。
- `1`：出现临时段或临时段确认路径。

当存在临时段时，程序继续检查临时段是否确认，或是否被新的极值破坏并回退到主段延长。

完整历史扫描结束时，如果主段或临时段仍未退化为空，也会以最后一笔的 `known_at_bar_index` 输出。这类尾部段可能是 `confirmed=false`。

### 6.4 兼容性首段删除

`reference_segments` 在结果生成后执行：

```python
if result:
    result.pop(0)
```

也就是说，扫描得到的第一个参考段会被丢弃。这是当前实现继承参考语义的兼容行为，文档和测试都应以实际输出为准。

### 6.5 段输出锚点

每个段输出为 `segment`：

- `start_bar_index = start_line.start.bar_index`
- `end_bar_index = end_line.start.bar_index`
- `start_time = start_line.start.time`
- `end_time = end_line.start.time`

向上段：

- `start_price_i64 = low(start_line)`
- `end_price_i64 = high(end_line)`

向下段：

- `start_price_i64 = high(start_line)`
- `end_price_i64 = low(end_line)`

只有 `confirmed=true` 的段会进一步参与标准段中枢、背驰和买卖点计算。

## 7. 段中枢

段中枢输出名为 `segment_zhongshu`。程序先把已确认段转换成段级 `LineObject`，再复用 `reference_centers(segment_lines)`。

### 7.1 与笔中枢的差异

段中枢与笔中枢使用相同参考扫描逻辑，但有两个关键差异：

- 输入只包含已确认段。
- 只接受 `ZD < ZG` 的正宽重叠区间。

因此，点接触 `ZD == ZG` 可以成为笔中枢，但不会成为标准段中枢。

### 7.2 输出字段

段中枢输出字段包括：

- `analysis_level = segment`
- `component_kind = segment`
- `component_count`：参与段切片数量。
- `zd_i64` / `zg_i64`：冻结核心。
- `dd_i64` / `gg_i64`：完整外包络。
- `z_i64 = (ZD + ZG) // 2`
- `status`: `confirmed`、`extended` 或 `left`
- `leave_direction`: `up`、`down` 或空

对象 ID 由段级核心起始段和种子结束段生成。

## 8. 背驰

背驰对象输出为 `divergence`。当前实现只在段级别上计算，依赖段中枢和固定 MACD 柱面积。

### 8.1 MACD 柱面积

引擎在逐 K 线更新时同步计算 MACD：

- 快线 EMA：12，对应系数 `2 / 13`
- 慢线 EMA：26，对应系数 `2 / 27`
- DEA：9，对应系数 `2 / 10`
- 柱值：`2 * (DIFF - DEA)`

第一根 K 线把快线和慢线初始化为收盘价，DEA 初始化为 0。

某一段的 MACD 面积：

- 向上段：累加该段起止 `bar_index` 范围内所有正柱。
- 向下段：累加该段起止 `bar_index` 范围内所有负柱绝对值。

### 8.2 通用背驰判断

给定参考段和当前段，通用条件为：

- 两段方向一致。
- 参考段 MACD 面积大于 0。
- 当前段 MACD 面积小于参考段 MACD 面积。

趋势背驰额外要求当前段创新高或创新低：

- 向上趋势：当前段高点必须高于参考段高点。
- 向下趋势：当前段低点必须低于参考段低点。

盘整背驰不要求创新高或创新低。

向上段背驰输出 `top_divergence`，价格取当前段高点。向下段背驰输出 `bottom_divergence`，价格取当前段低点。

### 8.3 盘整背驰

盘整背驰对应 `a + Z + c`：

- 中枢必须为 `status = left`。
- `exit_index` 必须存在。
- `base_index >= 1`，以便找到中枢前同方向参考段。
- 当前段为 `exit_index`，也就是离开中枢的段。
- 当前段之后必须已经有一段反向段完成，使用 `exit_index + 1` 的 `known_at_bar_index` 作为背驰确认时间。
- 参考段为中枢 `base_index` 之前最近的同方向段。
- 不要求当前段相对参考段创新高或创新低。

### 8.4 趋势背驰

趋势背驰对应两个相邻段中枢构成的 `b + Z2 + c` 比较：

- 第一中枢和第二中枢都必须已有 `exit_index`。
- 第一中枢的结束位置必须早于第二中枢的起点。
- 第二中枢的离开段之后必须还有一段用于确认。
- 两个中枢的完整外包络必须严格分离：
  - 第二中枢 `DD >` 第一中枢 `GG`，方向为上。
  - 第二中枢 `GG <` 第一中枢 `DD`，方向为下。
- 外包络只接触不算严格趋势。
- 参考段为第一中枢的离开段。
- 当前段为第二中枢的离开段。
- 参考段、当前段、第二中枢离开方向必须一致。
- 当前段必须相对参考段创新高或创新低。

如果同一段同时出现趋势背驰和盘整背驰，趋势背驰优先，盘整背驰会被过滤掉。

## 9. 买卖点

买卖点对象输出为 `trade_point`。当前实现包含标准一、二、三类点，以及项目定义的类一、类二、类三点。

### 9.1 一类点

一类点直接由背驰生成：

趋势背驰：

- `bottom_divergence` 生成 `buy_1`
- `top_divergence` 生成 `sell_1`
- `signal_class = standard`

盘整背驰：

- `bottom_divergence` 生成 `class_buy_1`
- `top_divergence` 生成 `class_sell_1`
- `signal_class = class_like`

一类点沿用背驰的发生位置、价格和 `known_at_bar_index`。

### 9.2 二类点

对每个一类点，程序检查：

```text
second_index = divergence.segment_index + 2
```

也就是一类点之后的第一个完成反向再返回结构。

二类点方向要求：

- 买侧一类点要求 `second_index` 段方向为 `down`。
- 卖侧一类点要求 `second_index` 段方向为 `up`。

二类点价格：

- 买侧取 `second` 段低点。
- 卖侧取 `second` 段高点。

强弱规则：

- 如果二类点与同侧严格三类点在同一 `bar_index` 且同一价格重合，`strength = strongest`。
- 买侧二类点价格不低于一类点价格，或卖侧二类点价格不高于一类点价格，`strength = normal`。
- 如果二类点价格创出不利新极值，但 `second_index` 自身存在盘整背驰确认，`strength = weakest`。
- 创出不利新极值且没有自身盘整背驰确认时，不生成二类点。

标准一类点生成 `buy_2/sell_2`，类一类点生成 `class_buy_2/class_sell_2`。

### 9.3 三类点

严格三类点直接从段中枢离开后的第一段回抽判断：

前置条件：

- 中枢 `status = left`。
- `exit_index` 存在。
- `return_index = exit_index + 1` 存在。

三买：

- 中枢 `leave_direction = up`。
- 离开段方向为 `up`。
- 回抽段方向为 `down`。
- 回抽段低点 `> ZG`。
- 输出 `buy_3`，价格为回抽段低点。

三卖：

- 中枢 `leave_direction = down`。
- 离开段方向为 `down`。
- 回抽段方向为 `up`。
- 回抽段高点 `< ZD`。
- 输出 `sell_3`，价格为回抽段高点。

严格三类点 `signal_class = standard`，`known_at_bar_index` 使用回抽段的确认位置。

### 9.4 类三点

程序保留严格三类点，同时在以下条件下额外生成类三点：

- 当前严格三类点之前存在同侧一类来源。
- 最近的同侧一类来源是 `class_like`。

此时：

- `buy_3` 额外生成 `class_buy_3`。
- `sell_3` 额外生成 `class_sell_3`。
- 类三点引用最近同侧类一来源的 `reference_object_id`。

## 10. 走势状态

当前程序中的“走势”主要由两个对象表达：`movement_state` 和 `center_monitor`。它们都基于标准段中枢生成。

### 10.1 中枢内走势状态

每个段中枢都会生成一个水平状态对象：

- 参与构件数量 `component_count <= 3` 时，`state_type = consolidation`。
- 参与构件数量 `component_count > 3` 时，`state_type = centre_oscillation`。
- 价格锚点为中枢中轴 `Z`。
- 时间范围为中枢起止时间。
- `reference_object_id` 指向对应段中枢。

### 10.2 中枢迁移状态

程序按时间顺序比较相邻段中枢完整外包络：

- 当前中枢 `DD >` 前一中枢 `GG`，生成 `centre_migration_up`。
- 当前中枢 `GG <` 前一中枢 `DD`，生成 `centre_migration_down`。
- 否则不生成迁移状态。

迁移状态的起点使用前一中枢结束位置，终点使用当前中枢结束位置，价格锚点使用当前中枢 `Z`。

### 10.3 Z/Zn 中枢监视

对每个段中枢的每个参与段，程序生成一个 `center_monitor`：

- 当前段区间中点 `Zn = (low + high) // 2`。
- 中枢中轴 `Z = (ZD + ZG) // 2`。
- `relative_position`：
  - `Zn > Z` 为 `above`。
  - `Zn < Z` 为 `below`。
  - 相等为 `equal`。
- `strength`：
  - 向上段且 `Zn > Z`，或向下段且 `Zn < Z`，为 `strong`。
  - `Zn != Z` 但不满足强势方向，为 `weak`。
  - `Zn == Z` 为 `neutral`。
- 最近三个 `Zn` 严格递增时，`migration_warning = up`。
- 最近三个 `Zn` 严格递减时，`migration_warning = down`。

这些对象用于图表展示和对象树观察，不直接等同于完整多级别走势分类。

## 11. 缓存与持久化

缠论结果写入：

```text
cache/chan/<cache_key>/
```

主要文件：

- `fractals.parquet`
- `bi.parquet`
- `segments.parquet`
- `zhongshu.parquet`
- `segment_zhongshu.parquet`
- `movement_states.parquet`
- `center_monitors.parquet`
- `divergences.parquet`
- `trade_points.parquet`
- `events.parquet`
- `checkpoints/*.bin`
- `manifest.json`
- `_SUCCESS`

写入流程使用临时目录，全部 Parquet、检查点和 manifest 写完后才写 `_SUCCESS`，最后原子提交目录。已有完整 `_SUCCESS` 缓存会直接复用。

`cache_key` 由 Go 侧按数据集、数据修订、算法定义、参数和计算模式生成。Python 端还会校验算法 `kind`、`algorithm_id`、`algorithm_version` 和 `source_hash` 必须与当前代码定义一致。

## 12. 前端展示边界

Vue 不重新计算缠论。前端只按范围读取 Go 返回的已缓存对象，并用 `ChanPrimitive` 绘制：

- 分型：三角标记。
- 笔：蓝色线，临时笔用虚线/半透明。
- 段：黄色线。
- 笔中枢：主图矩形区域。
- 段中枢：主图矩形区域和外包络。
- 走势状态：水平状态线。
- Z/Zn 监视：中轴到 Zn 的点线。
- 背驰和买卖点：信号标记和文字标签。

对象树中缠论作为 `StrategySource` 分组展示，不把 Python 语义对象持久化为普通用户绘图对象。

## 13. 未尽事宜与后续可重新考量部分

以下内容是当前实现尚未覆盖、或已经实现但未来可以重新评估的部分。

### 13.1 分型与包含关系

- 当前分型要求中间独立 K 线高低点同时严格高于或低于两侧。等高、等低、单侧突破等边界全部不构成分型。后续如果要贴合其他流派，需要明确等值处理规则。
- 包含关系首个二元关系存在特殊逻辑，主要为兼容参考实现。后续可以增加更直观的单元测试和注释，降低维护成本。
- 当前包含方向完全由上一根独立 K 线方向继承。是否引入更明确的初始方向配置，可以后续评估。

### 13.2 笔

- 最少独立 K 线数量固定为 5，当前不是参数。若未来支持不同缠论流派，可以把它纳入算法参数，但必须进入缓存键和算法版本。
- 当前临时笔会作为 `bi` 对象输出，但不参与后续结构计算。前端展示、对象树命名和用户理解上可继续优化。
- 笔终点确认依赖后续同类分型价格分离，这是参考实现规则。是否需要提供“更早确认”或“严格确认”两套模式，需要以算法版本区分。

### 13.3 笔中枢

- 笔中枢允许 `ZD == ZG` 点接触，而段中枢要求 `ZD < ZG`。这是一处当前语义差异，后续可以明确是否笔中枢也应统一为正宽区间。
- 中枢核心在延长时保持冻结，不随后续同奇偶笔重新计算。该行为贴合当前参考扫描，但和某些中枢动态收缩定义不同。
- `component_count` 和外包络使用完整切片，而核心重叠判断只按同奇偶步进扫描。这个实现应继续通过跨实现黄金样本保护。

### 13.4 段

- 段算法是参考 `_NCHDUAN` 的直接移植，内部状态较复杂，可读性有限。后续可在不改变输出的前提下重构为更明确的状态机。
- 段扫描使用每笔起点对应原始 K 线参与高低点判断，这是参考兼容行为。若未来改为笔端点价格或独立 K 线价格，需要升级算法版本并重建缓存。
- 当前会删除扫描结果中的首个段。该行为已经被测试保护，但业务解释仍需继续沉淀。
- 尾部未确认段会输出为 `confirmed=false`。是否要在完整历史计算中隐藏尾部未确认段，后续可结合用户展示需求评估。

### 13.5 段中枢与走势

- 当前段中枢只做单级别结构，不做多级别递归和上下级别联动。
- 走势状态目前只有 `consolidation`、`centre_oscillation`、`centre_migration_up/down`，属于工程观察对象，不是完整走势类型体系。
- `center_monitor` 的强弱和迁移预警基于 `Zn` 与 `Z` 的简单关系及最近三个 `Zn` 单调性。后续可重新考量是否引入力度、持续时间、离开方向、成交量或 MACD 组合判定。

### 13.6 背驰

- MACD 参数固定为 12/26/9，且柱面积使用内部同步计算结果。若允许用户配置 MACD 参数，必须进入算法参数、缓存键和文档。
- 当前趋势背驰要求两个段中枢完整外包络严格分离。对“接触算不算趋势”的处理已经选择为不算，后续若改变必须升级算法版本。
- 盘整背驰不要求创新高或创新低，这是当前项目规则。是否区分更强/更弱盘整背驰，可以后续扩展。
- 当前没有使用成交量、持仓量、波动率或斜率作为背驰辅助过滤。

### 13.7 买卖点

- 一类点完全由背驰派生，没有独立的非背驰一类点规则。
- 二类点强弱规则是项目化定义：重合三类点为最强，不破一类点为一般，破一类点但自身盘整背驰为最弱。其他流派的二类点定义尚未实现。
- 类一、类二、类三点是项目定义的类信号生命周期，不等同于标准买卖点。后续可以在 UI 和文档中继续区分标准点与类点。
- 当前严格三类点只检查离开后的第一回抽段是否不回中枢。更复杂的多次回抽、失败后重判、次级别确认尚未实现。

### 13.8 工程与性能

- 结构对象在每次确认新笔后整体重扫并用事件流同步差异。该方式利于正确性和确定性，但未来大样本可考虑增量化。
- 稳定 ID 使用截断哈希，碰撞概率极低但理论上不是零。若需要审计级全局唯一性，可以保留完整哈希或引入更长 ID。
- 事件流支持删除和修订，但用户界面对“历史对象被修订”的解释仍可继续增强。
- 检查点已支持恢复一致性，但当前检查点主要服务缓存和测试；后续可以用于长任务恢复或局部重算。

### 13.9 策略消费边界

- 缠论策略只消费 `segment_zhongshu`、`divergence`、`trade_point` 等因果事件，不改变缠论对象本身。
- 当前已实现的单级别策略不包含跨周期联动、低级别确认、涨跌停、流动性、滑点动态模型或换月规则。
- 后续若把策略规则反向影响缠论对象展示，必须保持对象模型分离，不能把策略事件写回缠论缓存。

## 14. 当前测试保护重点

当前测试覆盖的关键语义包括：

- 包含关系按既定方向合并。
- 三独立 K 线严格分型由右侧独立 K 线封存。
- 笔首尾相接、方向交替，复杂端点序列与参考实现一致。
- AOL9 前缀段结果与参考金样一致。
- 笔中枢从同奇偶笔建立并可延长、离开。
- 段中枢必须正宽，且 `DD <= ZD < ZG <= GG`。
- 事件流前缀不变。
- 检查点恢复后事件和对象与不中断计算一致。
- 趋势背驰比较 `b` 与 `c`，而不是 `a` 与 `c`。
- 外包络接触不构成严格趋势。
- 盘整背驰不要求创新高或新低。
- 三类点使用离开后的第一回抽段。
- 二类点创出不利新极值时必须有自身盘整背驰确认。
