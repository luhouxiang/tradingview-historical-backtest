# 缠论算法说明文档

## 1. 实现边界

缠论由 Python 端实现，Go 和 Vue 不实现第二套算法。Go 只负责提交计算任务、校验路径、读取缓存结果和对外返回范围数据；Vue 只负责把 Python 生成的语义对象绘制到主图和对象树。

当前缠论实现位于：

- `python/src/tvbt/chan/engine.py`：核心结构计算。
- `python/src/tvbt/chan/algorithm.py`：计算任务入口。
- `python/src/tvbt/chan/storage.py`：Parquet 与 manifest 写入。
- `python/src/tvbt/chan/events.py`：因果事件生成。
- `python/src/tvbt/chan/signals.py`：线段中枢、背驰和买卖点信号。

## 2. 输入与输出

输入是 Go 指定的标准化 K 线 Parquet 与 meta 文件。Python 不扫描任意目录，不接受浏览器直接调用。

输出写入 `cache/chan/<cache_key>/`，主要包括：

- `fractals.parquet`：分型。
- `bi.parquet`：笔。
- `segments.parquet`：段。
- `zhongshu.parquet`：笔中枢。
- `segment_zhongshu.parquet`：标准线段中枢。
- `divergences.parquet`：背驰。
- `trade_points.parquet`：一、二、三类买卖点。
- `events.parquet`：因果事件流。
- `manifest.json`：算法、参数、数据修订、文件哈希和对象计数。
- `_SUCCESS`：缓存原子完成标记。

## 3. 因果规则

所有对象都必须携带稳定 ID、对象修订号、确认位置和 `known_at_bar_index`。对象的理论起点可以早于确认时点，但图表和回放只能在 `known_at_bar_index` 到达后显示或更新该对象。

关键约束：

- 不得把完整历史最终结果倒灌到更早回放时点。
- 不得根据当前屏幕范围决定缠论计算起点。
- 回放区间位于历史中段时，也必须从数据集起点逐 K 线累积状态到目标位置。
- 缓存键必须包含数据修订、算法 ID、算法版本、源码哈希、参数和计算模式。

## 4. 处理流程

### 4.1 包含关系处理

算法先将原始 K 线转换为独立 K 线序列。存在包含关系时，按已经建立的方向合并高低点，保证后续分型、笔和段基于稳定的独立 K 线结构。

### 4.2 分型识别

分型使用三根独立 K 线的严格极值关系：

- 顶分型：中间独立 K 线高点严格高于左右两侧。
- 底分型：中间独立 K 线低点严格低于左右两侧。

分型不是出现后立即无条件确认，而是等待后续独立 K 线提供足够信息，确认时间不得早于可因果知道该分型的时点。

### 4.3 笔生成

笔由交替方向的顶/底分型构成。端点选择遵循参考实现规则：

- 相邻笔首尾直接相接。
- 笔方向严格上下交替。
- 同类分型在形成有效笔前，使用更极端的分型替换候选端点。
- 端点之间满足最少独立 K 线数量要求。
- 不使用屏幕范围、固定预热根数或 ATR 门槛改变笔的历史语义。

### 4.4 笔中枢

笔中枢基于连续笔的价格重叠区域生成。实现遵循参考算法的 `compute_bi_pivots/process_down_up` 规则，输出稳定的 ZD/ZG、起止笔、确认位置和事件时间。后续相交笔可以延长中枢时间范围，但不得把确认时间提前到形成条件之前。

### 4.5 段

段以 `_NCHDUAN` 及其辅助规则为参考。算法从笔序列中发现首段，并按正向/反向确认、临时段修订和最终确认规则生成 `segments.parquet`。段作为独立语义对象进入事件流和图表层，默认在主图以黄色线显示。

### 4.6 标准线段中枢

标准线段中枢使用已确认段作为构件，只接受 `ZD < ZG` 的正宽重叠核心。输出同时保留冻结核心 `ZD/ZG`、震荡包络 `DD/GG`、中轴 `Z`、结构级别和构件数量。标准线段中枢用于背驰、三类买卖点和策略状态机。

### 4.7 背驰与买卖点

背驰和买卖点以标准线段中枢为基础：

- 趋势背驰使用 `a + Z1 + b + Z2 + c`，要求两个中枢完整外围范围不重叠，力度比较发生在中枢离开段之后。
- 盘整背驰使用 `a + Z + c`，生成类一买卖点生命周期。
- 严格三类点要求离开段后的回抽段不回到对应中枢核心区间。
- 信号分为标准一、二、三类点以及类一、类二、类三信号，并记录 `signal_class` 与 `strength`。

策略只消费这些已确认语义对象，不直接读取 UI 当前窗口，也不绕过统一回放/回测入口。

## 5. 前端展示模型

Vue 将每个缠论算法实例表示为一个 `StrategySource`。对象树按类别展示分型、笔、段、笔中枢、标准线段中枢、背驰和买卖点；不会为每个 Python 对象创建普通用户绘图节点。

图表绘制使用批量 `ChanPrimitive`，默认显示笔、段、笔中枢、标准线段中枢、背驰和买卖点，分型可在对象树中单独开启。点击信号只改变选择状态；点击小锁才执行定位，并按对象锚点加载必要历史窗口。

## 6. 测试要求

缠论测试重点不是只看最终对象数量，而是验证因果语义：

- 前缀不变性：前 N 根 K 线的已知结果不因追加未来 K 线而改变。
- 检查点恢复一致性：从检查点恢复后的对象和事件与一次性计算一致。
- 事件单调性：`known_at_bar_index` 不倒退，确认时间不早于理论形成时间。
- 缓存命中：相同数据修订、算法版本、源码哈希和参数的请求复用同一不可变缓存。
- 范围查询：Vue 只按当前可视范围读取已有缓存，不触发 Python 重算。
