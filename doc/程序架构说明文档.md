# 程序架构说明文档

## 1. 系统目标

本项目是面向国内期货历史行情的类 TradingView 回放与回测系统。系统只处理历史数据，不接入实时行情和实盘交易。首期以文件为持久化基础，由 Go 提供公共 API 和任务管理，由 Python 负责指标、缠论、回放和策略计算，由 Vue 3 负责图表展示与交互。

## 2. 三端职责

### Vue 前端

- 负责 UI、图表渲染、坐标投影、十字线、命中检测和用户交互。
- 通过 `/api/v1` 调用 Go，不直接读取磁盘、Parquet 或 Python。
- 维护多窗格布局、右侧对象树、底部回放/回测/优化面板、用户绘图和工作区状态。
- 缩放、拖动、调整窗格尺寸只触发前端重绘或 Go 范围查询，不触发 Python 重算。

### Go 服务

- 扫描 `data_root/history` 中的原始 TXT，识别数据源并执行标准化导入。
- 维护 catalog、读取标准化 Parquet、按范围向前端返回 K 线。
- 提供 `/api/v1` 公共接口，管理长任务生命周期、取消、超时和错误映射。
- 通过本机 `/internal/v1` 调用 Python，并校验所有文件引用位于 `data_root` 内。
- 保存工作区布局、绘图、运行结果索引和浏览器日志。

### Python 计算服务

- 负责 MA、MACD、ATR、缠论结构、策略状态机、回放、回测和参数评估。
- 只读取 Go 指定的标准化 Parquet，不自行扫描任意磁盘目录。
- 计算结果写入 `cache` 或 `runs` 目录，并通过 `_SUCCESS` 标记原子完成。
- 所有因果对象和信号携带 `known_at_bar_index`，禁止把未来结果提前显示到历史时点。

## 3. 目录与数据流

主要目录：

- `cmd/chartd`：Go 公共服务入口。
- `internal`：Go 业务模块，包括配置、导入、catalog、K 线读取、任务、回放、回测、优化、工作区和日志。
- `python/src/tvbt`：Python 内部计算服务、指标、缠论、策略和存储逻辑。
- `web/src`：Vue 3 前端组件、图表层、指标面板、对象树和 API 客户端。
- `contracts`：OpenAPI、JSON Schema 和示例契约。
- `config/app.yaml`：运行配置。
- `trading-data`：默认运行数据根目录，不作为源码语义的一部分。

导入数据流：

1. 用户或启动脚本把原始通达信 TXT 放入 `data_root/history`。
2. Vue 调用 Go 的 `POST /api/v1/datasets/scan` 扫描源文件。
3. Vue 调用 `POST /api/v1/datasets/import` 创建导入任务。
4. Go 解析 TXT、映射交易日历、写入 `normalized/<dataset_id>/<revision>/`。
5. `bars.parquet`、`meta.json`、`quality.json` 均写入成功后，最后提交 `_SUCCESS`。
6. Go 更新 catalog，Vue 通过 `GET /api/v1/datasets` 选择可用数据集。

图表与计算数据流：

1. Vue 选择数据集后，通过 Go 查询最新尾部 K 线。
2. 前端接近左侧缓存边界时再向 Go 请求更早范围。
3. 指标、缠论、回放、回测由 Vue 创建任务，Go 转发给 Python。
4. Python 写入不可变缓存或正式 run，Go 只按范围读取结果并返回给 Vue。
5. Vue 只绘制已知时点可见的对象，不在浏览器中重新实现权威算法。

## 4. 初始标的配置

初始期货标的由 `config/app.yaml` 的 `chart.initial_instrument` 控制：

```yaml
chart:
  initial_instrument: AO2609
```

规则：

- 字段缺失或为空时，默认使用 `AOL9`。
- 写成 `AOL9` 时，启动后优先加载 `SHFE.AOL9.5m`。
- 写成 `AO2609` 时，启动后优先加载 `SHFE.AO2609.5m`。
- 启动脚本只准备对应的 `samples/30#<标的>.txt` 样例；如果样例不存在会明确失败。

## 5. 持久化与一致性规则

- 原始 TXT 永不原地修改。
- 数据集身份由 `dataset_id` 和 `data_revision` 共同确定。
- 时间字段保留 `trading_day`、`timestamp_utc`、`source_hhmm` 和 `bar_index`。
- 缺失 K 线不自动补齐，零成交量 K 线不删除。
- 价格在持久化、订单和成交中使用定点整数。
- 文件写入采用同目录临时文件加原子重命名，成功目录最后写 `_SUCCESS`。
- 完成的正式回测 run 不覆盖，缓存和 run 不混用。

## 6. 任务与接口

公共接口统一为 `/api/v1`，内部 Python 接口统一为 `/internal/v1` 并只监听本机回环地址。长任务立即返回 `job_id` 或 `run_id`，前端轮询状态；首期不使用 WebSocket。

典型公共接口包括：

- `GET /api/v1/health`
- `POST /api/v1/datasets/scan`
- `GET /api/v1/source-files`
- `POST /api/v1/datasets/import`
- `GET /api/v1/jobs/{job_id}`
- `GET /api/v1/datasets`
- `GET /api/v1/datasets/{dataset_id}/bars`
- `POST /api/v1/calculations`
- `POST /api/v1/replays`
- `POST /api/v1/backtests`
- `GET/PUT /api/v1/workspaces/...`

## 7. 日志与运维边界

Go、Python、Vue 均输出结构化 NDJSON 日志。每条日志必须携带真实源文件、源行号和函数名。单个活动日志文件最大 50 MiB，当前文件加备份最多 10 个。日志失败不得中断导入、图表、指标或回测。

启动脚本会检查固定运行时版本、准备样例数据、启动 Python/Go/Vite，并等待 Go 与 Python 健康检查通过后再打开页面。端口冲突时应在启动子服务前失败，避免只留下部分服务。
