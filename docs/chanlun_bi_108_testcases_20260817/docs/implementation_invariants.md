# 笔实现不变量

## 1. 数据层次

必须同时保留三层对象：

```text
raw_kline -> processed_kline -> fractal -> bi
```

`processed_kline` 应保存其成员原始K线，以及高点、低点分别来自哪根原始K线。合成K线的显示时间不能替代极值来源时间。

## 2. 包含关系

设K线区间为 `[low, high]`。若两区间互相包含：

- 向上处理：`high=max(high1,high2)`，`low=max(low1,low2)`；
- 向下处理：`high=min(high1,high2)`，`low=min(low1,low2)`。

新合成K线必须再按时间顺序与下一根比较，不能一次性对整组取全局极值。

## 3. 分型

在无包含K线序列上，对连续三根K线：

- 顶分型：中间K线的高点与低点都高于两侧；
- 底分型：中间K线的高点与低点都低于两侧；
- 单纯三根上升或三根下降K线不构成分型。

顶价格是顶分型最高点，底价格是底分型最低点。

## 4. 成笔

一笔连接处理后的有效顶、底分型：

- 底后顶：向上笔；
- 顶后底：向下笔；
- 端点分型的成员K线不得重叠；
- 两端分型之间至少有一根处理后K线不属于任一端点分型。

在同一笔有效区间内：

```text
up_bi.start_price  = min(processed.low)
up_bi.end_price    = max(processed.high)
down_bi.start_price = max(processed.high)
down_bi.end_price   = min(processed.low)
```

以上断言针对处理后K线。对原始K线直接做此断言可能被包含处理反例击穿。

## 5. 同类分型取舍

没有有效反向分型分隔时：

- 两个顶候选，后顶更高则删除前顶；
- 两个底候选，后底更低则删除前底；
- 同价候选先暂存；当随后相反分型出现时，按第77课的先后规则保留最先的等价极值。

不能为了保持既有绘图不变而锁死一个尚未完成的笔端点。

## 6. 当下性

至少区分：

| 状态 | 含义 |
|---|---|
| `candidate_fractal` | 中间K线已出现，但右侧确认尚不足 |
| `confirmed_fractal` | 三K结构及包含处理已完成 |
| `candidate_bi` | 一端已确定，另一端仍可能被同类更极端分型替换 |
| `confirmed_bi` | 满足端点、间隔和交替规则 |
| `invalidated` | 后续信息证明候选不能成为笔端点 |

理论端点时间与确认时间必须分开。禁止事后把端点价格写回更早时间并假定当时可成交。

## 7. 与线段的边界

线段由至少三笔构成，并按特征序列分型确认破坏。第78课允许线段结构端点不是整段最高/最低点，并可为上层分析另做标准化；这个例外不改变笔规则。

建议字段分开：

```text
segment.structural_start/end
segment.range_high/low
segment.normalized_start/end
```

## 8. 中枢边界

笔不能直接组成缠论最低级别中枢。中枢模块必须接收线段或更高级别走势类型，不能直接接收 `bi[]`。
