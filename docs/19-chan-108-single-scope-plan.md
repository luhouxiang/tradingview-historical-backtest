# 108 课校准后的单周期详细方案

日期：2026-09-05。状态：**A–E 已按里程碑 14 实施；F 研究验证未启动**。阅读入口：[校准结论](17-chan-108-recalibration-20260905.md)、[62 项算法与场景](18-chan-108-expanded-algorithm-catalog.md)。

## 1. 目标和结束边界

本轮目标是把可用算法说清楚：来自哪课、现系统怎样实现、哪里不同、能用于什么场景、怎样在单标的单周期下检验。不是启动下一轮代码开发，也不是做收益承诺。

固定输入为一个数据集修订和一种 K 线周期；使用现有 Python 权威事件链。允许同一周期多条 MA/MACD/BOLL 参数线，允许该周期形成分型、笔、线段及现有线段中枢。**不加入多级别递归、多 K 周期、跨标的/板块联动、区间套、核心/机动双账本。**原文必须依赖这些关系的算法，只记录未覆盖原因。

原研究交付是三个文档及逐课来源清单。用户随后授权实施 A–E，现已写入 `docs/09-implementation-roadmap.md` 并逐项完成；F 仍是后续研究任务。

## 3. 方案一：线段实际区间贯通

**问题**：现线段端点可非极值，而上层范围 helper 仍只取端点高低。依据是[第 78 课](https://chanlun108.cn/chanzhongshuochan108ke/78.html)。

输入：已确认线段、其组成笔及处理后 K 来源、已知时间；不让策略重新扫描原始数据。输出建议在权威线段事实内增加独立的实际低/高及极值来源引用，字段具体名称先在 contracts 定义。

处理步骤：

1. 明确区间取自该段哪些成员。建议以所属笔/处理后 K 的价格范围为依据；是否含端点分型支持区外沿需要反例确认，不能随意扩大到相邻段。
2. 保留 `start/end` 结构锚点；另外计算 `range_low/high`，同时保存造成极值的原始 K 来源。
3. 中枢前三构件交集、外围 DD/GG、三类点回试极值、Zn 输入统一使用相同 range profile。
4. 极值或组成关系发生修订时，发布当时已知的新 revision；对已生成交易只追加因果后果，不回写旧成交。
5. 升算法/缓存版本，旧 run 和旧 profile 仍可查看并明确版本；不能覆盖完整历史正式结果。

最小逻辑示例：结构端点 `120→100`、内部高点 `140`。结构绘图仍连 120 与 100；区间计算用 `[100,140]`。另两构件区间 `[110,130]`、`[105,125]` 时三者交集为 `[110,125]`，只看前段端点会误成 `[110,120]`。这只是范围算术示例，正式测试还必须提供合法笔/特征序列生成它。

验收：普通极值端点段与旧版一致；非极值段出现预期差异；真实行情只列受影响对象和依赖数量；前缀与恢复一致；Go/Vue 只传递和展示，不能重新算 range。

## 4. 方案二：三类点边界与首回试资格

现 profile 按[第 20 课](https://chanlun108.cn/chanzhongshuochan108ke/20.html)文字取闭区间；[第 54 课](https://chanlun108.cn/chanzhongshuochan108ke/54.html)图例对触边有不同处理。本轮不替用户改选规则。建议把现有选择标为兼容 profile，并将严格脱离作为可单独检验的备选。

假定向上离开已完成，冻结核心 `[100,110]`；除最后两行外均为第一次已完成回试：

| 回试最低价 / 状态 | 当前闭区间 profile | 严格脱离备选 | 解释 |
|---|---|---|---|
| 109 | 无 B3 | 无 B3 | 进入核心 |
| 110 | B3 | 无 B3，触边震荡 | 文义冲突的唯一价位边界 |
| 111 | B3 | B3 | 严格在核心外 |
| 111，但回试尚未完成 | 仅候选/观察 | 仅候选/观察 | 未知将来最低价 |
| 首次回试 109，后来第二次 111 | 不补成首次 B3 | 不补成首次 B3 | 不重新消费失去的首次资格 |

卖点镜像：当前 `high <= ZD`，备选 `high < ZD`。点中枢 `[100,100]` 依旧是结构对象，不能因严格三类点 profile 就删除它。

输出应能追溯中枢、离开对象、首回试对象、回试序号、比较值、profile 和最早可用时点。需统一所有消费层：三类点确认、回归核心、五状态、B2/B3 同点、持仓退出。尤其同根出现“触边三买”和“触边回归”时，必须由明确事件语境/优先级解决，禁止同一逻辑无条件开平。

## 5. 方案三：线段规则与背驰资格的证据表

为每个结构判定输出必要的来源 ID，先用于解释和验收，避免给图形加一个无法审查的“严格缠论”标签。

| 对象 | 必须可核验的证据 | 本轮不作的推断 |
|---|---|---|
| 笔 | 两个有效分型成员、中心跨度、全支持窗口、被淘汰同类候选、区间极值 | 五个中心跨度覆盖 K 等于五根原始 K |
| 无缺口段破坏 | 标准特征元素、分型、第一二元素无缺口、分界包含处理 | 任何突破前笔就等于段结束 |
| 有缺口段破坏 | 缺口与第二特征序列的完整确认链 | 第一处分型出现即可确认 |
| 趋势背驰 | 固定层趋势、b/c 的身份与方向、新极值、力度模型、确认对象 | 当前单线段代理已证明第 37 课所有内部级别前提 |
| 盘整背驰 | 同一中枢归属、同向可比段、有效力度、已知时间 | 自动等同标准 B1/S1 |

依据：[第 67 课](https://chanlun108.cn/chanzhongshuochan108ke/67.html)、[第 71 课](https://chanlun108.cn/chanzhongshuochan108ke/71.html)、[第 77 课](https://chanlun108.cn/chanzhongshuochan108ke/77.html)、[第 37 课](https://chanlun108.cn/chanzhongshuochan108ke/37.html)。这里的缺口是特征元素价格区间关系，与下一节的原始行情价格缺口分开。

## 6. 方案四：均线面积与平均力度

[第 15 课](https://chanlun108.cn/chanzhongshuochan108ke/15.html)给出了均线间面积以及面积除时间的平均力度。它适合新增为**旧均线系统辅助指标**，不能取代后期结构背驰。

输入：同周期权威 MA_short、MA_long、已确认吻结束事件及下一次吻开始事件；均线参数不由未来表现选择。输出：累计面积、已知时长、平均力度、上一可比同向完成段 ID、比值、`running/completed` 状态。

建议离散研究 profile（属于工程公式）：令 `d_i = abs(MA_short_i - MA_long_i)`，取前一吻结束到当前的右端矩形积分 `area(t)=Σ d_i × Δu_i`，`average(t)=area(t)/ΣΔu_i`。首版 `u` 固定为观察 K 单位；若改成真实交易时间，应另设 profile，不能让夜盘休市和周末悄悄放大面积。零时长/预热不足输出 null 和原因。真实时刻与 K 单位不能混比。

例：等长间隔的差值 `[0,1,3,2,0]` 对应四个区间面积 6、平均 1.5；后一完成同向段 `[0,1,2,1,0]` 面积 4、平均 1.0。输出力度收缩证据，**不推导一定反转或直接发标准一买**。运行中与已完成段比较必须标为暂态，后续可增强，不能提前固化背驰。

验收：等长/变长、MA 交叉边界、无后续吻、零差值、负价格、相同面积不同持续时间；显示当前累积值不影响已完成段。默认无订单，先在原有信号上观察增量解释能力。

## 7. 方案五：价格缺口生命周期

[第 77 课](https://chanlun108.cn/chanzhongshuochan108ke/77.html)讨论缺口强弱及其结构关系。首版只做可观察的生命周期，暂不声称通过缺口就能预测后续强弱。

输入：相邻原始 K 的时间、交易日、OHLC，及现有笔/段确认事件。上涨缺口为 `current.low > previous.high`，下跌镜像；等号为接触而非正宽缺口。交易数据缺失与价格缺口完全不同，零成交 K 不删除，缺 K 不填补。

输出：形成时刻、上下边界、方向、当前回补极值、第一次部分回补时刻、完全跨回对侧边界时刻、关联转折、未知/失效原因。例：前高 100，后低 105，形成上跳区间；随后最低到 104 是部分回补，降至 100 或更低按本 profile 记完全回补。这个 OHLC 定义只说明价格跨越边界，不证明空隙内每个 tick 都真实成交。

处理：用运行中的最深回补位置单调更新；禁止提前把未回补标为永久强势。是否将“回补且导致本级转折”命名为弱缺口，需要等待已确认结构并明确观察窗口。隔夜/session 边界单列标签，但不改夜盘自然日期映射。

验收：等号、连续跳空、跳回但无中间成交、同根跨多边界、缺失数据、零成交量、来源修订。仅辅助图层与统计，不自动触发订单。

## 8. 方案六：回归深度、旧中枢链位置与净空间

依据：[第 29 课](https://chanlun108.cn/chanzhongshuochan108ke/29.html)、[第 99 课](https://chanlun108.cn/chanzhongshuochan108ke/99.html)。目标是描述当前单层事实，不推断高级别走势。

输入：已确认转折来源、当时冻结的末中枢核心与外围、当时已知旧同层中心链、后续已知价格/完成段。输出分开两层：价格触及是即时观察；完成段回归是结构确认，不混为一个事件。

例：末中心外围 `[90,120]`、核心 `[100,110]`，底转折端点 80：

| 后续最高价格 | 即时观察 | 不能宣称 |
|---|---|---|
| 89 | 未到末中心外围 | 已满足回归 |
| 90 | 触及外围 DD | 已回核心 |
| 100 | 触及核心下沿 | 已完全穿越 |
| 105 | 进入核心 | 后面一定成上升趋势 |
| 110 或更高 | 到达/穿越核心上沿，分别记等号与越界 | 交易必然盈利 |

若继续触及旧的更早同层中枢，记录“深入第几个旧中心”，并按旧趋势方向解释；不能笼统地把所有深入都叫利空。中心链在信号可用时冻结，后来才出现的中心不回填为过去的目标。

净空间另以**拟执行价**计算。例如端点 80 到 DD=90 有 10 点理论观察空间，但确认后拟成交已为 94，则向 DD 回归不再有正向空间。费用/滑点扣减只是一种入场可行性估计，不能冒充目标一定实现。

信号时的估计只使用当时已知价格和预设成本；下一根真实开盘价只能在撮合时复核，不能回填为上一根的入场选择条件。`volume_cap_ioc` 用当根总成交量限制模拟成交也是明确的历史撮合假设，并非开盘前已知容量；`unlimited` 结果不能作为真实流动性证据。

验收：外围/核心等号、点中枢、价格触及后未形成完成回试、来源修订、阴阳镜像、目标落在执行价另一侧、不同合约乘数和费用单位。

## 9. 方案七：分型与单标的均线观察

三项相互独立，均为观察输出。

- **分型特征**：直接输出影线、实体、范围、收盘位置等数值，优先保留 C-058 的明确强反转轮廓。长影阈值、综合分及权重没有原文唯一值，因此不新增默认总分。[第 82 课](https://chanlun108.cn/chanzhongshuochan108ke/82.html)
- **单标的 MA 等级**：从用户事先给定、且记录可用时间的反弹起点累积攻克历史；默认沿用 P-028“收盘严格高于”定义。当前 `aux_ma_sector_rotation` 入口要求多数据集，单标的版本应复用其数学函数并独立适配，不能假造第二个标的绕过校验。[第 106 课](https://chanlun108.cn/chanzhongshuochan108ke/106.html)
- **压制均线一致性**：在同一固定层趋势的已确认反弹上，记录最近触及/受压均线是否与首次相同。“触及”可按区间相交，“受压”需要随后多少根或哪个完成段的确认——这是待固定的参数，不直接用均线改变结构级别。[第 106 课](https://chanlun108.cn/chanzhongshuochan108ke/106.html)

其中多条 MA 使用同一 K 线输入，不引入第二 K 周期；不计算板块均值、横截面排名或跨标的轮动。

## 10. 方案八：确认延迟与已有策略对照

每个实际进场保留四个时点：理论端点 `t0`、结构确认 `t1`、策略可用 `t2`、实际成交 `t3`。要求 `t0 <= t1 <= t2 <= t3`；同一根内的收盘和下一根开盘不能只靠 bar_index 等号混淆。端点若不是来源极值时刻，另存来源引用。

统一诊断建议：

- 确认延迟、可用到成交延迟的中位数和高分位；样本不足不报虚假稳定分位数。
- 理论端点到可用/成交的顺逆方向价格偏移；含单位和 tick_size。
- 三类点等号命中数量、首回试失效数量、同点 B2/B3 数量；按 profile 对齐来源而非只按日期配对。
- 实际范围改变引起的中枢、背驰和买卖点差异数；区分未确认对象变化和已确认事实变化。
- 毛空间、费用后空间、实际成交率、净收益、最大回撤、交易数；没有成交应如实为零而非给出胜率。

先对照 T08 与 T05 的持仓目标，再对照 T09 的首中枢资格；不要强行“统一”退出规则。T13/T14 对各自原策略只增加 MACD 入场过滤，保持已确认 C-070 的资格即时消费规则。当前 T01 只执行部分五状态动作，也应明确写为所选交易子集。

采用现有单数据集 Research Study 即可；禁止把新增另一种周期或另一标的当成完成前提。训练选择、验证和成本/延迟压力沿用已有流程。即使单标的结果良好，也只能满足现项目的探索性证据范围。

## 11. 跨模块数据约束与测试矩阵

本方案中的拟议输出都应包含数据身份、算法/profile 版本、稳定来源 ID、revision、时间/价格锚点、最早可用时点及事实/辅助属性。这里给出的是需求，不在本轮新增 JSON Schema。

| 验收维度 | 必须验证的行为 |
|---|---|
| 正例/反例 | 合法结构产生预期结果；缺少任何必要前提不能误发 |
| 等号 | tick 整数比较；三类点、点中枢、回归、均线攻克分别依各自 profile |
| 未完成 | 分型右 K、特征序列、回试、吻面积的暂态不能冒充确认 |
| 事件修订 | 来源改变时追加 revision/失效；历史成交/run 不覆盖 |
| 前缀不变性 | 独立运行到任意切点，与完整事件流在该点可知事实相等 |
| 恢复 | 检查点恢复与不间断运行的事件、对象身份、已知时间一致 |
| 数据边界 | 原 TXT 不改、零成交不删、缺 K 不补、夜盘用交易日历 |
| 执行边界 | 下一可交易时点、手续费/滑点、容量和无法成交明确处理 |
| 三端边界 | Python 算法；Go 读取校验与 API；Vue 投影；缩放不触发算法 |

首个代码里程碑只验收其实际改动对应的测试，不因这是一份完整方案就一次修改所有模块。研究文档和原课配图只能帮助构造用例，合法 OHLC 数值与预期事件还需独立验证。
