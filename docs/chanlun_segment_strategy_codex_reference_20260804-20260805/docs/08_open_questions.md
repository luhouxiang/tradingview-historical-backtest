# 08 尚需项目确认的实现问题

Codex 在落地前应逐项检查。没有宿主项目答案时，不要猜测。

## P0：影响结构定义

### 1. 线段完成与破坏算法

本次可恢复讨论没有完整保存以下底层规则：

- K线包含处理方向；
- 顶底分型确认；
- 笔的最小间隔和共用K线；
- 线段特征序列；
- 第一/第二种线段破坏；
- 缺口如何形成和确认线段；
- 未完成线段何时重绘、何时冻结。

必须引用宿主仓库已有实现或另建底层规格。本包不能替代它。

### 2. “线段中枢”与“次级别走势中枢”的映射

项目硬规则选择线段中枢作为标准路径，但需确认：

- 三条原始线段直接构造中枢；或
- 先把线段组合成次级别走势，再由三个完成走势构造中枢。

两者会产生不同级别、数量和信号延迟。必须通过 `component_kind` 分开。

### 3. 同级中枢非重叠口径

选择其一：

- `core_only`：只比较 `[ZD,ZG]`；
- `oscillation_envelope`：比较 `[DD,GG]`/外围波动，较接近第20课；
- 更严格的递归扩张判定。

该选项直接影响趋势数量和趋势背驰。

### 4. 多义分解

走势允许多种合理分解。生产策略采用：

- 单一确定性分解；
- 多候选分解后按优先级选取；或
- 同时保留并要求信号在多个分解上共识？

无论选哪种，都需版本化、可重放。

## P1：影响信号确认

### 5. 末段“创新高/低”的比较基准

需明确比较：

- 前一同向连接段极值；
- 前一个中枢外围 `GG/DD`；
- 整个趋势截至末段前的极值。

建议在测试数据上列出反例后决定。

### 6. 力度的主度量

结构力度尚需选定：

- 价格变化/时间；
- 斜率；
- 成交量或成交额归一化；
- MACD柱面积；
- DIFF/DEA极值；
- 多度量的有序判定。

MACD只能辅助，但程序仍需一个明确、可复现的结构力度定义。

### 7. 低级别完成确认

B1/B2/B3中的“低级别走势完成”要落到哪种事件：

- 低级别B1/S1；
- 低级别线段反向确认；
- 低级别走势类型完成；
- 固定K线延迟代理。

固定K线延迟只是近似，应有独立标签。

### 8. 点状中枢

当前文档允许 `ZD == ZG`。需确认宿主项目是否：

- 保留为合法退化中枢；
- 要求至少一tick宽；
- 根据品种流动性设最小宽度。

不能用浮点epsilon隐式决定。

## P2：影响指标与执行

### 9. 指标参数

- MACD周期与面积积分边界；
- BOLL周期、倍数与跨级别映射；
- MA5/MA10在不同市场周期上的定义；
- `Zn` 使用完整次级别区间还是端点区间。

### 10. 市场数据制度

- 夜盘和跨日session；
- 期货主力连续/真实合约；
- 复权方式；
- 涨跌停、停牌；
- 最小tick变化；
- 成交量跨合约可比性。

### 11. 执行模型

- 收盘确认后下一tick还是下一根开盘成交；
- 限价/市价；
- 部分成交；
- 手续费和滑点；
- 仓位与风险上限。

这些不改变结构，但决定可交易结果。
