# 13D 本机内存修复与验收

## 原因

切换合约时，AppShell 会自动创建全历史指标及缠论计算；展开回测面板、选择固定级别中枢决策树不需要提交正式回测。2026-09-06 00:34:12 的日志记录了 `SHFE.SSL9.5m` 的后台 `calculation`，任务最后停留在 running。

旧 `run_chan` 每 1024 根 K 线导出包含全部已知历史的 JSON 检查点，并在字典中保留所有检查点直到结束。其累计空间随历史长度近似二次增长。另外，完整事件列表、转换后的事件字典、Arrow 表和全部输入列有重叠存活。合约切换只清空 Vue 对象，没有取消 Python 任务；内部计算线程也没有并发保护。

已有 AOL9 缓存的 69 个检查点共 3,442,588,327 字节。修复后 SSL9 完整计算生成的 77 个检查点共 3656.80 MiB；旧实现仅保留这些检查点就需要约 3.57 GiB，尚未计算引擎状态、事件及临时副本。这是代码和文件大小证据，不是冒险重跑旧实现得到的整机峰值。

## 实现

- 输入按 4096 根 K 分批读取，仍从数据集第一根开始。
- 检查点使用相同规范 JSON 流式写入 `data_root/tmp`；生产内存中只保留文件引用。
- 事件到达批量阈值后按每批 4096 条写入 Parquet，保留完整事件序号、修订和因果时间；终态表也分批转换。
- 临时文件随成功、失败或取消清理；正式缓存仍最后写 `_SUCCESS` 并原子重命名。
- Python 内部只有一个计算执行槽，等待任务可取消，HTTP 查询和取消不受该槽阻塞。
- Vue 在合约切换和卸载时取消旧图表计算，等待迟到提交清理；旧轮询不能覆盖新数据集状态。Go 不复用正在取消的任务，旧任务结束也不能清除替代任务的登记。
- 缠论每 64 根 K 及检查点前检查内存：默认进程阈值 2048 MiB，可用系统内存低于 512 MiB 时也停止。通过 `RESOURCE_MEMORY_LIMIT` 返回明确原因并显示在对象树中。

没有修改算法规则、价格、确认时间、全历史范围或不可变正式 run。缓存 Schema 仍为 4，检查点格式仍为 v1；源码哈希自动变化，旧缓存不会冒充新计算。OpenAPI 仅补充已有 Error 模型的资源保护错误说明并重新生成类型。

## 真实数据验收

使用指定 Python 3.14.4，在本机完整运行 `SHFE.SSL9.5m`，revision 为 `sha256:777869e8be935f7ae587540eb30ff782f92de22bf8a97b31a94f9fcd7a7eb709`。

| 项目 | 结果 |
| --- | --- |
| 完整覆盖 | 79,761 根，bar_index 0–79,760 |
| 事件数 | 373,167 |
| 检查点 | 77 个，最大单文件 91.39 MiB |
| Python 进程 PrivateUsage 采样峰值 | 852.84 MiB（250 ms 采样） |
| 总耗时 | 601.21 秒，含结果与检查点写入 |
| 结果提交 | `_SUCCESS` 存在，临时目录清理完成 |

可重复脚本：`scripts/measure-chan-memory.py`。记录位于 `trading-data/acceptance/memory-13d-ssl9-memory.json`，完整结果位于相邻 `memory-13d-ssl9` 目录。每次重测必须换用新的 `--output`，防止覆盖验收证据；必须使用项目指定解释器：

```powershell
& 'D:\ProgramData\anaconda3\envs\pydev3.14\python.exe' scripts/measure-chan-memory.py --data-root trading-data --meta normalized/SHFE.SSL9.5m/777869e8be93/meta.json --output acceptance/memory-13d-ssl9-repeat
```

测量针对 Python 计算进程，不代表整个系统或浏览器总内存。保护是协作式检查，并非操作系统硬配额；检查点导出、单根复杂更新以及外部应用仍可能造成瞬时波动。完整检查点仍占用磁盘，首次计算仍需时间。本次没有为减少内存而缩短历史，也没有覆盖原始数据或正式回测。

## 回归与样例

Go 全量测试、go vet；Python 259 项测试（含前缀不变性）、mypy、Ruff；Vue 31 个文件共 119 项测试、类型检查、生产构建；OpenAPI 与 24 个 Schema 示例均通过。新增回归覆盖完整事件与检查点字节一致性、检查点不积累在内存、取消清理、排队取消、内存阈值及合约切换迟到响应。

隔离的 Chromium 全栈 E2E 通过：AOL9 默认加载、K 线显示、正式回测完成、历史交易定位、鼠标拖动后向右补数至最新、刷新恢复同一 run。该 E2E 使用脚本生成的 3150 根样例；SSL9 内存验收使用现有真实标准化数据。新增可复用测量脚本，没有生成替代真实历史的行情。
