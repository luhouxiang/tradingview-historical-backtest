# 给 VS Code Codex 的参考提示

## 实现任务模板

```text
你正在处理缠论线段中枢策略代码。先完整阅读本目录的 AGENTS.md、README.md、
docs/02_domain_model.md、docs/03_center_detection.md、docs/04_signal_rules.md、
docs/07_state_machine_and_backtest.md 和 docs/08_open_questions.md。

要求：
1. 项目硬规则优先；区分原文定义、项目约定和实现建议。
2. 先识别宿主仓库已有的级别、线段完成、事件与价格精度模型，不要另造平行体系。
3. 标准路径使用 component_kind=segment；笔中枢不得混入。
4. 任何确认结构只能消费当时已完成事件。
5. 所有信号分离 endpoint_time 与 confirmed_at；回测成交不得早于 confirmed_at。
6. 价格边界使用整数tick；B3严格 > ZG，S3严格 < ZD，等于视为中枢延伸。
7. MACD、均线、成交量、BOLL、分型、Zn只能作为辅助或风险过滤。
8. 先补不变量和边界测试，再实现策略。
9. 若 docs/08_open_questions.md 的某项会改变结果，先列出可选口径、影响和推荐，等待确认。

请先输出：
- 现有代码与参考规范的映射；
- 确定项/冲突项/未决项；
- 最小改动计划；
- 测试计划。
在我确认前，不要大规模重构。
```

## 代码审查模板

```text
请按本参考包审查当前实现，重点寻找：
- 未完成组件参与中枢或信号确认；
- 中枢核心在延伸中漂移；
- 突破后未等第一次完整回试就确认B3/S3；
- 把触边误判为三买卖点；
- 只有一个中枢却确认趋势背驰；
- 末段未创新高/低却确认标准背驰；
- 用未完成末段MACD面积确认背驰；
- 二买低于一买但未标弱、无盘整背驰；
- endpoint_time 被当作可成交时点；
- 笔中枢与线段中枢混用；
- 浮点epsilon改变tick边界；
- 指标绕过结构直接生成买卖点。

按严重度列出问题，给出文件/行、触发例、违反的规则、最小修复和回归测试。
```
